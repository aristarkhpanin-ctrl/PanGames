# «Гавань» — дизайн-документ и техническое задание

Рабочее название: **Гавань**. Воксельный веб-симулятор островного город-государства.
Стек: three.js (воксельный 3D) · бэкенд с аккаунтами и визитами · реальное время с офлайн-прогрессом.
Документ написан как рабочая спецификация: его можно резать на куски и скармливать Claude Code по этапам.

---

## 0. Одно предложение и эмоциональное ядро

> Ты приплываешь на пустой остров с четырьмя людьми и обустраиваешь место, где им будет хорошо.

Игрок здесь не менеджер эффективности, а хозяин дома. Ключевое переживание — **тихая забота**: ты возвращаешься, видишь, что Мира наконец переехала в дом у скалы, что вечером все собрались у костра, что цветы, которые ты посадил вчера, зацвели. Отсюда следует главный принцип: игра **никогда не создаёт срочности**.

### Устав антистресса (нарушать нельзя)

Это не пожелания, а инварианты. Каждый пул-реквест проверяется по ним.

1. **Никто не умирает и не уходит.** Ни от голода, ни от холода, ни от обиды. Максимум — грустит.
2. **Нет проигрыша, нет отката, нет разрушений.** Построенное остаётся навсегда.
3. **Нет врагов, войн, воровства, налогов, штрафов, поломок.** Погода — атмосфера, не угроза.
4. **Нет таймеров с наказанием.** Стройка идёт в фоне; если ты не пришёл вовремя — она просто ждёт готовой.
5. **Офлайн не наказывает.** Пока тебя нет, остров живёт медленно и спокойно. Настроение жителей не падает ниже «спокойно» (порог 55) в твоё отсутствие.
6. **Любое действие отменяемо.** Снос в первые 10 минут — возврат 100% ресурсов, потом 70%. Перемещение здания — бесплатно и всегда.
7. **Ноль соревнования.** Никаких лидербордов, рейтингов островов, сравнений с другими. Гости не оценивают.
8. **Проблемы сообщаются шёпотом.** Не красный алерт «НЕТ ЕДЫ», а строчка в дневнике: «Ким подумывает, что у восточных домов не хватает колодца».
9. **Никаких пушей типа «вернись скорее, урожай сгорит».** Уведомления только добрые и редкие: «На остров приплыла лодка с подарком».
10. **Нет монетизации, ускоряющей время за деньги.** Если когда-то будет монетизация — только косметика.

### Чего в игре нет (частые рефлексы, которые надо давить)

Голода со смертью, здоровья, болезней, преступности, пожаров, набегов, «счастья ниже 30% = бунт», обязательных ежедневных входов, энергии/жизней, ограничения по времени на постройку сессии, случайных катастроф.

## 1. Технологический стек и почему именно так

### Монорепозиторий

```
pnpm workspace
├── apps/web        — клиент: Vite + TypeScript + three.js + React (только HUD) + zustand
├── apps/server     — Fastify + ws + Drizzle ORM + PostgreSQL
├── apps/worker     — процесс догоняющей симуляции и фоновых задач (можно слить с server на старте)
└── packages/shared — типы, каталоги контента, ядро симуляции (изоморфное, без зависимостей)
```

**Ключевое архитектурное решение:** ядро симуляции (`packages/shared/sim`) — чистые детерминированные функции без импортов из three.js, DOM или Node. Один и тот же код исполняется на сервере (авторитетно) и на клиенте (предсказание). Это даёт мгновенный отклик интерфейса при серверной честности.

### Клиент

- **three.js напрямую**, без react-three-fiber. Воксельный мир требует ручного контроля над геометрией, мешингом и инстансингом; R3F на этом слое только мешает. React живёт **поверх** канваса и не знает о сцене ничего, кроме сериализованного состояния из стора.
- **Web Worker** для генерации мешей чанков (greedy meshing) и для A*. Главный поток не должен фризить никогда.
- **zustand** как единственный стор состояния UI и зеркала игрового состояния.
- Никакого физического движка. Жители ходят по навигационной сетке, гравитация не нужна.

### Сервер

- **Fastify** (REST для команд и данных) + **ws** (стрим тиков и событий).
- **PostgreSQL + Drizzle**. Состояние острова хранится гибридно: реляционные таблицы для сущностей, которые надо искать (пользователи, острова, визиты), и `jsonb`-снимок для тела мира (воксели, здания, жители) — так проще версионировать и грузить одним запросом.
- **Авторизация:** magic-link на почту + JWT в httpOnly cookie. OAuth добавляется позже одной ручкой. Пароли не заводим — меньше кода и меньше ответственности.

### Деплой

Клиент — статика на Vercel/Netlify. Сервер — Fly.io или Railway (нужен постоянный процесс под ws). База — managed Postgres. Ассеты (палитры, каталоги) идут в бандл, не в CDN — их мало.

## 2. Мир

### Метрика и размеры

| Параметр | Значение |
|---|---|
| Размер вокселя | 0.5 м |
| Остров (XZ) | 160 × 160 вокселей (80 × 80 м) |
| Высота (Y) | 96 вокселей, уровень моря Y = 32 |
| Чанк | 32 × 32 × 96 |
| Чанков | 25 (5 × 5) |
| Жителей максимум | 60 |
| Зданий максимум | ~250 |

Остров намеренно небольшой и **не расширяется бесконечно**. Ограниченность — часть терапии: ты обустраиваешь конкретное место, а не гонишься за ростом. Расширение есть, но дискретное: 3 соседних островка, соединяемых мостами, открываются по главам (+40% площади каждый).

### Генерация

Детерминированная по сиду острова (`island.seed`, целое из 32 бит). Клиент и сервер обязаны получать идентичный результат из одного сида — генератор живёт в `shared`.

Пайплайн:
1. **Форма берега:** радиальный шум (симплекс, 3 октавы) по расстоянию от центра → маска суши. Гарантируем связность и минимум одну удобную бухту.
2. **Высоты:** фрактальный шум, 4 октавы, потолок 24 вокселя над уровнем моря. Скалы только в одном секторе — остров должен читаться как «пляж, луг, лес, скала».
3. **Биомы:** пляж (песок), луг (трава), роща (трава + деревья), скалы (камень), мелководье. Биом = функция высоты, расстояния до воды и одного дополнительного слоя шума.
4. **Ресурсные точки:** глина у ручья, залежи камня в скалах, косяки рыбы в бухте, ягодные кусты в роще, песок на пляже. Каждая точка — сущность с запасом и **регенерацией** (см. §4).
5. **Одна «диковинка»** на остров из пула (кривое дерево-великан, каменная арка, тёплый источник, затонувшая лодка) — точка притяжения для декорирования и первая тема в дневнике.

### Материалы вокселей

`AIR, WATER, SAND, DIRT, GRASS, STONE, CLAY, WOOD, LEAVES, PATH, PLANK, BRICK, GLASS, THATCH, FLOWER_*`

Цвет берётся из палитры (§8), а не из текстур. Текстур в проекте нет вообще — только цвет вершины плюс мягкое AO. Это радикально упрощает пайплайн и держит стиль.

### Рендер

- **Greedy meshing** по чанкам в воркере; один меш на чанк на материал-группу.
- **AO** запекается в вершинные цвета при мешинге (классический voxel-AO по 3 соседям на угол).
- **Вода** — отдельный полупрозрачный слой с лёгкой синусоидой по вершинам и градиентом глубины. Никакого скринспейс-рефлекшена.
- **Деревья и декор** — `InstancedMesh` по типу объекта, не воксели чанка.
- **Жители** — `InstancedMesh` из 6 боксов (тело, голова, 2 руки, 2 ноги), анимация процедурная (синус по фазе шага). 60 персонажей = 360 инстансов, это ничто.
- **Свет:** один directional (солнце по циклу дня) + hemisphere. Тени — PCF soft, только для солнца, каскад один, радиус вокруг камеры.
- **Камера:** орбитальная RTS-камера. ЛКМ — выбор, ПКМ/пробел+drag — панорама, колесо — зум (границы 15–90 м), Q/E — поворот на 45°. Только 8 фиксированных углов поворота? Нет — плавный поворот, но с «примагничиванием» к 45° при отпускании. Наклон ограничен 25–70°.
- Целевой бюджет: **60 fps на интегрированной графике**, < 400 draw calls, < 250k треугольников.

## 3. Время

| Величина | Значение |
|---|---|
| 1 игровой час | 60 секунд реального времени |
| 1 игровой день | 24 минуты |
| Тик симуляции | 10 секунд реального = 10 игровых минут |
| Тиков в дне | 144 |

Цикл суток: рассвет 6:00, день, закат 19:00, ночь. Ночью жители спят, производство идёт на 30% (только те, у кого «ночная» черта), остров освещается фонарями — это самое красивое время, и на него работает режим «Смотреть».

### Офлайн-прогресс

Две разные модели симуляции — это важно понять до написания кода:

- **Живая (agent-based).** Работает только пока игрок онлайн. Каждый житель — агент с состоянием, путём и задачей. Тик 10 секунд.
- **Сводная (aggregate).** Работает при возвращении игрока. Не симулирует агентов по одному: берёт прошедшее время, состав жителей, здания и назначения, считает производство/потребление аналитически по формулам, применяет результат одним куском.

Правила догона:
- Полная скорость первые **12 часов** отсутствия, затем коэффициент **0.6**, полный потолок накопления — **48 часов**. Дальше остров «дремлет»: ресурсы не растут, но и ничего не портится.
- Настроение жителей в офлайне стремится к 65 (спокойно), не выше и не ниже. Пока тебя нет, драмы не происходит.
- Стройки завершаются в офлайне нормально.
- При заполнении склада производство встаёт (ресурсы не пропадают, ничего не портится).

При входе — экран **«Пока тебя не было»**: 3–6 карточек (что построилось, что накопилось, кто с кем подружился, что появилось в дневнике). Это не отчёт, а маленькая радость: спокойные формулировки, никаких «ВЫ ПОТЕРЯЛИ».

## 4. Ресурсы и экономика

### Базовые (добываются)

`wood` дерево · `stone` камень · `clay` глина · `sand` песок · `fiber` волокно · `fish` рыба · `fruit` фрукты · `grain` зерно · `wool` шерсть

### Переработанные

`plank` доски (2 wood → 1) · `brick` кирпич (2 clay → 1) · `glass` стекло (3 sand → 1) · `cloth` ткань (2 fiber + 1 wool → 1) · `bread` хлеб (3 grain → 2) · `tool` инструменты (1 plank + 1 stone → 1) · `meal` обед (1 fish/bread + 1 fruit → 2)

### Мягкие

- **`shell` ракушки** — валюта. Приходят от торговых лодок и гостей. Тратятся на редкие семена, декор, ускорение доставки (не производства).
- **`inspiration` вдохновение** — начисляется за красоту и события (праздник, новоселье, первая радуга). Открывает декоративные и культурные постройки. Никогда не тратится на еду/базу — это валюта уюта.
- **`comfort` уют** — не ресурс, а *производный показатель* района. Считается по радиусу от жилья: озеленение, чистая вода, свет, красота, близость к друзьям.

### Регенерация и отсутствие тупиков

Каждая ресурсная точка восстанавливается: деревья вырастают за 2 игровых дня, ягоды за 1, рыба в бухте — постоянный поток с потолком, камень и глина — конечные, но их залежи покрывают ~4× потребность полной застройки, плюс есть торговля с лодками. **Тупик невозможен по построению**: если кончился камень, лодка привезёт его за ракушки, а ракушки дают жители за просто хорошую жизнь.

### Формула производства

```
output_per_tick = base_rate
                × worker_efficiency        // 0.5 .. 1.3, от настроения и черт
                × building_level           // 1.0 / 1.35 / 1.75
                × resource_proximity       // 0.7 .. 1.0, от расстояния до источника
                × time_of_day_factor       // 1.0 днём, 0.3 ночью
```

`worker_efficiency` **никогда не опускается ниже 0.5** — грустный житель работает медленнее, но остров не сваливается в спираль смерти. Это прямое следствие устава.

### Склад

Стартовый лимит 200 на ресурс, +150 за каждый амбар. Переполнение → производство паузится с тихой пометкой на здании, ничего не теряется.

## 5. Жители

Главные герои игры. Всё остальное — декорация вокруг них.

### Личность

- **Имя** из кириллических пулов (короткие, тёплые, вымышленно-нейтральные: Мира, Ким, Тея, Осип, Лада, Юна, Гор, Веся…) + прозвище, которое появляется со временем («Мира, которая копает»).
- **Внешность:** цвет кожи, волос, одежды из палитры; 4 варианта причёски, 5 одежды. Всё воксельное, генерится из сида жителя.
- **Черты характера** — ровно 2 из 12: `ранняя пташка, сова, трудяга, мечтатель, садовник, рыбак, домосед, странник, весельчак, тихоня, аккуратист, коллекционер`. Черта меняет веса в выборе действий и даёт бонус к профильной работе (+15%).
- **Любимое место** — воксельная координата, которую житель выбирает сам через ~2 дня жизни. Он туда ходит отдыхать. Если ты поставишь там скамейку — +уют и запись в дневнике. Это одна из самых сильных эмоциональных механик, не срезать.

### Потребности

Шесть шкал 0–100, убывают со временем, восполняются действиями:

| Потребность | Убыль/час | Восполняется |
|---|---|---|
| Сытость | 4 | Еда дома / у общего очага |
| Отдых | 3 | Сон, скамейка, вид на море |
| Укрытие | — | Наличие дома (бинарно) + утепление |
| Общение | 2.5 | Разговор с другим жителем, площадь, праздник |
| Красота | 2 | Пребывание рядом с декором/природой |
| Занятие | 2 | Работа по душе, хобби-здание |

**Настроение** = взвешенное среднее (сытость 0.25, отдых 0.2, укрытие 0.15, общение 0.15, красота 0.1, занятие 0.15), сглаженное по 6 часам. Диапазоны: `светится 85+`, `радуется 70+`, `спокоен 55+`, `задумчив 40+`, `грустит <40`. Ниже 20 не опускается **никогда** — жёсткий пол в коде.

### ИИ (utility-based + FSM)

Состояния: `Idle, Walk, Work, Eat, Sleep, Socialize, Wander, Admire, Build, Haul, Celebrate`.

Каждые 30 игровых минут (или по завершении действия) агент считает полезность кандидатов:

```
score(action) = need_deficit(action) ^ 1.5
              × trait_weight(action)
              × time_of_day_weight(action)
              × (1 / (1 + distance / 20))
              + small_random(0.05)
```

Берётся максимум. Действие фиксируется до завершения (никакого дёрганья каждый тик). Ключ к «живости» — не сложность ИИ, а **читаемость**: игрок должен по позе и месту понимать, что человек делает, и панель жителя всегда говорит человеческим языком: «Идёт к пирсу — рыбачить» / «Сидит на своём камне, смотрит на воду».

### Навигация

- Навигационный граф строится из **проходимых поверхностных вокселей** (верхний твёрдый воксель с двумя воздушными над ним, перепад ≤1). Перестраивается инкрементально при изменении мира — только затронутые чанки.
- **A\*** в воркере, кэш путей по паре (from-chunk, to-target). Для популярных целей (общий очаг, склад) — flow field, один на цель.
- Дороги (`PATH`) снижают стоимость перехода вдвое. Это единственный «геймплей оптимизации», и он мягкий.

### Отношения и события жизни

- Совместное время в состоянии `Socialize` копит связь: `знакомы → приятели → друзья → близкие`.
- События: новоселье, первая дружба, годовщина, день рождения острова, праздник урожая. Каждое даёт вдохновение и запись в дневник.
- **Дети:** опционально (флаг `settings.families`), взросление 7 игровых дней, ребёнок не работает, но повышает уют вокруг. Пожилые не умирают — становятся `хранителями историй` (не работают, дают +уют и записи в дневник).
- **Новые жители приплывают сами**, когда на острове есть свободное жильё и средний уют выше 60. Не «нанимаются» — приходят, потому что тут хорошо. Появление всегда сопровождается открыткой: кто это и почему приплыл.

## 6. Здания

Каталог — данные, не код: `packages/shared/content/buildings.ts`. Каждое здание описывается одной структурой (см. §9), чтобы контент добавлялся без правок логики.

### Категории и стартовый каталог (v1 — 32 здания)

**Жильё:** Шалаш (4 wood) · Домик (12 plank, 6 stone) · Дом у скалы (20 plank, 12 brick, 4 glass) · Общий дом (30 plank, 10 cloth) — 4 жителя, +общение

**Добыча:** Место дровосека · Каменоломня · Глиняный карьер · Песчаная яма · Рыбацкий пирс · Ягодник · Поле (зерно) · Загон (шерсть)

**Переработка:** Лесопилка · Печь для кирпича · Стеклодувная · Ткацкая · Пекарня · Мастерская (инструменты) · Кухня (обеды)

**Быт:** Колодец · Амбар (+150 склада) · Погреб · Костровище (общий очаг, ключевое социальное здание) · Баня · Фонарь · Мост

**Культура и уют:** Скамейка · Площадь · Сад · Смотровая площадка · Дом историй (архив дневника) · Музыкальный помост · Купальня

**Декор:** клумбы, живая изгородь, флагштоки, гирлянды, каменные фонарики, качели, гамак — дешёвые, дают уют и вдохновение.

### Параметры каждого здания

`id, name, category, cost{}, buildTicks, footprint{w,h}, workers, jobType, output{}, input{}, comfortRadius, comfortValue, requires[], unlockChapter, description`

Стройка: жители с задачей `Build` носят ресурсы и работают. Ресурсы списываются **при заказе** (чтобы не было микроменеджмента), стройплощадка видна сразу как каркас, прогресс — по вертикальному «нарастанию» вокселей. Отмена заказа возвращает 100%.

Уровни: у производственных зданий 3 уровня (улучшение — не новое здание, а апгрейд на месте).

## 7. Прогрессия

Пять глав. Переход — не по «выполни 5 квестов», а по естественной вехе, которую игрок и так пройдёт. Названия глав появляются на экране крупно и тихо, один раз.

| Глава | Веха перехода | Что открывает |
|---|---|---|
| I. Прибытие | Все 4 стартовых жителя под крышей | Базовая добыча, костровище |
| II. Обустройство | 8 жителей, средний уют 50 | Переработка, амбар, дороги |
| III. Ремёсла | Первые инструменты | Стекло, ткань, апгрейды, второй островок |
| IV. Общность | 5 дружеских связей или первый праздник | Культура, праздники, третий островок |
| V. Гавань | Порт | Торговые лодки, визиты гостей, открытки |

**Вместо квестов — «желания».** Жители иногда хотят чего-то конкретного («Осип хотел бы, чтобы рядом с полем была скамейка»). Желание живёт в дневнике, не имеет таймера, не имеет провала. Выполнил — вдохновение и тёплая запись. Не выполнил — ничего не происходит, никогда не напоминаем дважды.

## 8. Визуальный стиль и интерфейс

### Направление

Не «мультяшный майнкрафт». Ориентир — **рассветный архипелаг**: мягкий свет, десатурированная зелень, тёплый песок, глубокая вода. Воксели крупные и чистые, без шума текстур, силуэты читаются с любого зума.

### Палитра

```
--sea-deep    #0E4F63   глубокая вода, самый тёмный тон сцены
--sea-shallow #3FA9A2   мелководье, акценты воды
--sand        #EAD9B0   песок, фон интерфейса
--leaf        #6E9E52   трава и листва
--leaf-shade  #3D6440   тени растительности, тёмный текст
--lamp        #F2C14E   свет фонарей, главный акцент интерфейса
--bloom       #C2547E   цветы, второй акцент (события, дневник)
```

Осознанно отказываемся от кремово-терракотовой связки и от «тёмная тема + кислотный акцент» — это визуальные дефолты, которые ничего не говорят про остров. Здесь акцент — цвет тёплого лампового света, потому что вечернее освещение и есть эмоциональная кульминация игры.

### Типографика (кириллица обязательна)

- **Дисплей:** `Unbounded` — только заголовки глав, экран загрузки, названия праздников. Скупо, крупно, с трекингом −2%.
- **Интерфейс:** `Golos Text` — вся навигация, панели, подписи. 15/22 базовый, 13/18 вторичный.
- **Числа:** `Golos Text` с табличными цифрами (`font-variant-numeric: tabular-nums`), чтобы счётчики ресурсов не прыгали.
- **Дневник:** рукописный кириллический шрифт (`Caveat` поддерживает кириллицу) — единственное место, где он используется. Это его подпись.

### Экраны и панели

- **Мир (основной).** Максимум канваса, минимум HUD.
  - Слева сверху: 4 ключевых ресурса. Клик — раскрывается полный список. Никаких 14 счётчиков всегда на виду.
  - Снизу по центру: строительство (категории иконками, при выборе — призрак здания на сетке с подсветкой валидности).
  - Справа: свёрнутая колонка жителей (аватар + микро-индикатор настроения). Клик — карточка.
  - Сверху по центру: время суток как тонкая дуга солнца, без цифр.
- **Карточка жителя.** Портрет, имя и прозвище, «сейчас: сидит у воды», настроение словом (не процентом!), 2 черты, связи с другими (кликабельно), текущее желание, кнопка «показать на острове».
- **Дневник острова** — signature-элемент. Хронологическая лента рукописных заметок от лица жителей: события, желания, наблюдения о погоде, мелочи. Это то, ради чего игрок возвращается. Генерируется из шаблонов с подстановкой имён и фактов (600+ вариаций достаточно, чтобы не приедалось за месяц).
- **Режим «Смотреть»** (клавиша `V`) — вторая signature-фича. UI полностью исчезает, камера медленно облетает остров по кривой, глубина резкости, звук природы усиливается. Никаких целей. Просто смотреть на то, что ты построил. Это и есть продукт.
- **Порт** — визиты, подарки, лодки.
- **Настройки** — звук, качество рендера, размер шрифта, `prefers-reduced-motion`, флаг семей.

### Тон текстов

Активный залог, без восклицаний, без геймификации. Кнопка «Построить» → тост «Построено». Пустой экран строительства: не «Здесь пока ничего нет», а «Начни с шалаша — Мира ночует под открытым небом». Ошибка: не «Ошибка 400», а «Не хватает 6 досок. Лесопилка сделает их к вечеру.»

### Звук

Ambient-слои (море, ветер, птицы, ночные цикады), микшируются по времени суток и позиции камеры. Музыка — один спокойный луп на главу, тихо, с возможностью выключить. Звуки действий мягкие и негромкие. Никаких резких «дзынь!».

### Доступность

Клавиатурная навигация по всем панелям, видимый фокус, `prefers-reduced-motion` отключает облёт и параллакс, масштаб интерфейса 100/125/150%, дальтоник-безопасные индикаторы (настроение словом и формой, не только цветом).

### Схема БД


`world_patch` хранит **только отличия от процедурной генерации** — так остров весит килобайты, а не мегабайты.

### REST

```
POST /auth/magic-link            { email }
GET  /auth/callback?token=...
GET  /me
POST /islands                    { name } → создаёт остров, сид, 4 жителя
GET  /islands/:id                → полное состояние + результат догона
POST /islands/:id/commands       { commands: Command[] }   ← единственная точка мутации
GET  /islands/by-code/:code      → гостевой режим, read-only
POST /islands/:id/gifts          { kind, messageId }
GET  /islands/:id/journal?after=
```

### WebSocket

`/ws?islandId=` — сервер шлёт `tick` (дельты ресурсов, состояния агентов, события), клиент шлёт только `command`. Между тиками клиент интерполирует движение сам.

### Команды (единственный способ менять мир)

```ts
type Command =
  | { t:'place_building'; typeId: BuildingTypeId; pos: Vec3; rot: 0|1|2|3 }
  | { t:'move_building'; id: string; pos: Vec3; rot: 0|1|2|3 }
  | { t:'remove_building'; id: string }
  | { t:'upgrade_building'; id: string }
  | { t:'assign_job'; villagerId: string; buildingId: string|null }
  | { t:'assign_home'; villagerId: string; buildingId: string }
  | { t:'terraform'; edits: Array<{ pos: Vec3; mat: number }> }   // лимит 64 за команду
  | { t:'plant'; pos: Vec3; kind: PlantId }
  | { t:'rename'; scope:'island'|'villager'; id?: string; name: string }
  | { t:'host_festival' };
```

Сервер валидирует всё: наличие ресурсов, проходимость, лимиты, права. Клиент применяет оптимистично и откатывает при отказе (визуально мягко, без модалок).

### Античит и доверие

Ресурсы, время и производство считает только сервер. Клиент не может «докрутить» время: `lastTickAt` серверный, догон вычисляется от серверных часов. Rate-limit на команды (30/сек), лимит на terraform. Учитывая отсутствие соревнования, глубже копать не нужно — красть тут нечего и не у кого.

### Визиты гостей

- Гость заходит по коду острова, получает **read-only** снимок: ходит камерой, смотрит жителей и дневник, ничего не меняет.
- Может оставить **подарок** (немного ресурсов из своего склада) и **открытку** — из набора готовых фраз и стикеров, без свободного текста. Это снимает всю модерацию разом и держит атмосферу.
- След визита: на берегу появляется цветок с именем гостя. Никаких оценок, счётчиков посещений и рейтингов.

## 11. План работ для Claude Code

Каждый этап — отдельная сессия с чистым контекстом. В начале каждой сессии давай Claude Code файл `CLAUDE.md` с уставом антистресса (§0) и текущим этапом — иначе он рано или поздно предложит «механику голода для челленджа».

**M0. Каркас.** pnpm-монорепо, TypeScript strict, Vite, Fastify, Drizzle, докер-компоуз с Postgres, ESLint/Prettier, health-check.
*Готово, когда:* `pnpm dev` поднимает клиент и сервер, клиент получает `{ok:true}` с `/health`.

**M1. Воксельный мир на экране.** Генератор острова в `shared`, чанки, greedy meshing в воркере, AO, палитра, вода, освещение, орбитальная камера.
*Готово, когда:* остров из сида отрисован, 60 fps, камера крутится, вода анимируется.

**M2. Мир редактируется.** Пикинг вокселей рейкастом, подсветка, terraform, посадка растений, локальный ремеш затронутых чанков.
*Готово, когда:* можно копать и сажать без фризов.

**M3. Жители живые.** Модель нужд, utility-ИИ, A* в воркере, инстансный рендер, процедурная анимация ходьбы, карточка жителя.
*Готово, когда:* 4 жителя ходят, спят, едят, и по экрану читается, кто что делает.

**M4. Строительство и экономика.** Каталог зданий, размещение с призраком, стройка, назначение работ, производство, склад, лимиты.
*Готово, когда:* цепочка «лес → лесопилка → доски → дом» работает от начала до конца.

**M5. Сервер-авторитет.** Команды, валидация, серверный тик, WebSocket, оптимистичный клиент, персистентность в Postgres, авторизация magic-link.
*Готово, когда:* обновление страницы не теряет ничего, а команды из devtools не дают ресурсов.

**M6. Офлайн и догон.** Сводная симуляция, коэффициенты, экран «Пока тебя не было».
*Готово, когда:* уход на сутки даёт правдоподобный и приятный результат.

**M7. Душа.** Дневник и шаблоны, желания жителей, отношения, любимые места, праздники, главы, режим «Смотреть», звук.
*Готово, когда:* тестер сам говорит «хочу посмотреть, что там у них».

**M8. Гости.** Порт, коды островов, гостевой режим, подарки, открытки, цветы на берегу, друзья.
*Готово, когда:* второй аккаунт заходит на остров и оставляет подарок.

**M9. Полировка.** Онбординг первых 60 секунд, доступность, мобильный тач-контроль, оптимизация, аналитика (только агрегаты, без слежки).

### Первые 60 секунд игрока

Море и лодка. Лодка причаливает, четверо сходят на берег. Камера опускается. Одна строка: «Здесь будет хорошо». Подсвечивается место под шалаш. Игрок ставит первый шалаш — и всё, дальше он свободен. Ни туториала на 15 шагов, ни модалок, ни стрелок. Дальнейшее объясняют желания жителей по мере надобности.

## 12. Риски и что резать первым

| Риск | Решение |
|---|---|
| Мешинг тормозит при редактировании | Ремешить только затронутые чанки, дельта-обновления, воркер-пул на 2 потока |
| A* на 60 агентах жрёт кадр | Бюджет 5 путей на тик, очередь, flow field для общих целей |
| Серверные тики не масштабируются | Живая симуляция только для онлайн-островов; офлайн — сводная. Это уже заложено |
| Игра ощущается пустой без давления | Лечится не сложностью, а дневником, желаниями и режимом «Смотреть». Если скучно — добавляй *жизни*, а не угроз |
| Скоуп разъезжается | Резать в таком порядке: дети → апгрейды зданий → доп. островки → праздники. Не резать: дневник, любимые места, режим «Смотреть» |

## 13. Промпт для `CLAUDE.md` в корне репозитория

```md
# Гавань — правила проекта

Веб-игра: воксельный островной город-государство про заботу о жителях. Антистресс-жанр.

## Нерушимые правила геймдизайна
Никто не умирает и не уходит. Нет проигрыша, врагов, катастроф, поломок, штрафов,
таймеров с наказанием и соревнования. Офлайн не наказывает. Любое действие отменяемо.
Настроение жителя не опускается ниже 20, эффективность работы — ниже 0.5.
Если предлагаешь механику — проверь её по этому списку. Механики «для челленджа» не добавлять.

## Технические правила
- packages/shared/sim — чистые детерминированные функции. Без three.js, DOM, Node API, Date.now(), Math.random().
  Время и случайность приходят аргументами (seeded PRNG).
- Мутировать состояние можно только командами через сервер. Клиент предсказывает, сервер решает.
- Мешинг и A* — только в воркерах. Главный поток не блокируется никогда.
- Контент (здания, черты, имена, шаблоны дневника) — данные в packages/shared/content, не код.
- TypeScript strict, без any. Тесты обязательны для sim/ и worldgen/.

## Тон интерфейса
Активный залог, сентенс-кейс, без восклицаний и геймификации. Настроение показывается словом,
а не процентом. Ошибка объясняет, что делать дальше.
```
