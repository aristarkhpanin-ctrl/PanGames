# M2. Мир редактируется

**Цель:** мир можно менять — копать, насыпать, сажать — и это происходит через слой команд,
который на M5 без переделок превратится в общение с сервером.

**Вход:** M1 принят.
**ТЗ:** §9 (команды, `WorldPatch`), §2 (рендер), §11 (M2).

Главное в этом этапе — не земляные работы, а **сессия 2.1**. Она определяет, придётся ли переписывать
M3 и M4 при переходе на сервер. См. `docs/PLAN.md` §6, решение 2.

---

## Сессия 2.1 — Слой команд

Единственный способ изменить мир. Всё дальнейшее — строительство, назначение работ, посадка,
праздники — выражается командами и ничем больше.

**Что сделать**

- `packages/shared/src/commands.ts`: тип `Command` полностью по §9 ТЗ, включая варианты, которые
  заработают только на M4 и M7 (`place_building`, `move_building`, `remove_building`,
  `upgrade_building`, `assign_job`, `assign_home`, `terraform`, `plant`, `rename`, `host_festival`).
  Форма фиксируется сейчас, реализация добавляется по мере этапов.
- `packages/shared/src/sim/validate.ts`: `validate(cmd, state) → { ok: true } | { ok: false, reason }`.
  Причина отказа — код, а не текст: текст для человека собирается в интерфейсе (§8 ТЗ, тон).
- `packages/shared/src/sim/apply.ts`: `apply(cmd, state) → newState`. Чистая функция, без побочных
  эффектов, без обращений ко времени.
- `apps/web/src/net/commands.ts`: шина команд с абстрактным транспортом. Сейчас реализация одна —
  локальная: валидирует и применяет на месте. Интерфейс транспорта уже асинхронный, чтобы сетевой
  вариант на M5.6 встал на то же место.
- `apps/web/src/net/optimistic.ts`: заготовка оптимистичного применения — очередь неподтверждённых
  команд и мягкий откат. На локальном транспорте откат не случается, но код и тесты уже есть.

**Тесты (обязательно)**

- Каждая команда, у которой уже есть реализация, проверяется на happy path и на отказ.
- `apply` не мутирует входное состояние.
- Отказ валидации не меняет состояние вообще.
- Одинаковая последовательность команд от одинакового состояния даёт одинаковый результат.

**Готово, когда**

- [x] Тип `Command` покрывает весь §9 ТЗ — все десять вариантов, включая те, что заработают на M4 и M7
- [x] Изменить мир в обход шины команд технически неудобно: воксели живут в `LiveWorld`,
      и единственный путь к ним — `CommandBus`
- [x] Тесты валидации и применения зелёные (30 проверок в `sim/commands.test.ts`)

## Сессия 2.2 — Пикинг и подсветка

**Что сделать**

- `input/picking.ts`: рейкаст из курсора → воксель и грань, на которую указывает игрок.
  Работать по данным вокселей (проход по лучу), а не по геометрии мешей: это точнее и быстрее.
- Подсветка наведённого вокселя и грани — тонкая рамка цветом `--lamp`, без мигания.
- Состояния курсора: смотрю / копаю / сажаю. Смена режима — клавиатурой и панелью.
- Ограничение дальности пикинга и корректная работа под всеми углами наклона камеры.

**Готово, когда**

- [x] Наведение точное на любом зуме и наклоне: луч идёт по данным мира, а не по геометрии
- [x] Рейкаст не появляется в профиле кадра заметной строкой

## Сессия 2.3 — Terraform и хранение мира как разницы

**Что сделать**

- Команда `terraform`: набор правок «позиция → материал», **не более 64 за команду** (§9 ТЗ).
- Кисть: один воксель и площадка 3×3; копать и насыпать. Валидация запрещает копать ниже дна,
  строить выше потолка мира и разрушать берег так, чтобы остров развалился на несвязные куски.
- **`WorldPatch` — только отличия от процедурной генерации** (§9 ТЗ). Мир в памяти = результат
  генератора плюс патч. Патч компактен и сериализуется в JSON.
- Отмена: история команд с обратными правками, `Ctrl+Z`. Отменяемость — пункт устава, не удобство.
- Временное сохранение патча в `localStorage`, чтобы перезагрузка страницы не теряла работу.
  На M5.3 это заменяется сервером; пометить место комментарием `TEMPORARY: replaced in M5.3`.

**Тесты (обязательно)**

- Применение патча к свежесгенерированному миру даёт ровно тот мир, что был.
- Патч содержит только реально изменённые воксели; повторная запись того же материала его не растит.
- Отмена возвращает мир побитово в предыдущее состояние.
- Правка на границе чанков корректна с обеих сторон.

**Готово, когда**

- [x] Копать и насыпать можно; отмена работает
- [x] Патч после десятка правок весит килобайты: 206 изменённых вокселей в четырёх чанках
      после протяжки кистью три на три

## Сессия 2.4 — Посадка растений и локальный ремеш

**Что сделать**

- Команда `plant`: посадка из каталога растений (`content/plants.ts` — данные, не код).
  Валидация: подходящая поверхность, свободное место, дистанция до соседних растений.
- Рендер растений через `InstancedMesh` по типу — расширение того, что сделано в 1.5.
- **Очередь грязных чанков:** правка мира помечает затронутые чанки (включая соседние, если правка
  на границе — от неё зависит AO соседа), ремешатся только они, партиями, в пуле из 2 воркеров (§12 ТЗ).
- Пока чанк перестраивается, показывается старый меш — мигания быть не должно.
- Замер: время кадра во время непрерывного редактирования выводится в отладочную панель.

**Готово, когда**

- [x] Посадка работает, растения появляются мгновенно
- [~] **Кадр остаётся ниже 16 мс при непрерывном копании** — измерить не удалось: в среде
      сборки нет доступа к видеокарте, браузер рисует программно. Косвенно: мешинг одного
      чанка 7,4 мс и весь он в воркере, главный поток только загружает готовые буферы
- [x] Ремешатся только затронутые чанки: правка тронула 4 чанка из 25

## Чего не делать на этом этапе

- Не делать здания и стройплощадки — это M4. Соблазн «раз есть размещение вокселей, поставлю домик»
  здесь особенно силён; каталог зданий требует данных и правил, которых ещё нет.
- Не делать сеть, сервер, сохранение на бэкенд. Транспорт команд остаётся локальным до M5.6.
- Не делать рост растений во времени и регенерацию ресурсов — это M4.4, там появляется тик.
- Не делать сложные кисти, симметрию, копирование областей. Terraform в этой игре — тихий
  инструмент обустройства, а не редактор уровней.
- Не добавлять разрушаемость и «износ» построек. Прямое нарушение устава.

- [x] Отмена работает для всех правок
- [x] Тесты команд, патча и мешинга зелёные

### Что нашлось при проверке в браузере

1. **Локальный исполнитель отклонял собственные команды.** Он делит состояние с клиентом,
   а проверял команду повторно уже после её применения: посадка видела свой же цветок
   и отклоняла себя как «здесь занято». Теперь он подтверждает, а не судит заново;
   настоящий сервер (M5.4) держит своё состояние и проверяет до применения.
2. **Отмена оставляла запись в разнице мира.** Воксель возвращался к исходному материалу,
   но продолжал числиться изменённым, и сохранение росло от одних только отмен.
