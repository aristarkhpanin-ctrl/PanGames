# M5. Сервер-авторитет

**Цель:** у игры появляется аккаунт, сохранение и честность. Обновление страницы ничего не теряет,
а команды, отправленные из консоли браузера, не дают ресурсов.

**Вход:** M4 принят.
**ТЗ:** §9 (схема БД, REST, WebSocket, команды, античит), §1 (сервер, авторизация), §11 (M5).

Этот этап дёшев ровно настолько, насколько аккуратно сделан M2.1. Ядро симуляции уже чистое и
изоморфное, слой команд уже есть — остаётся перенести исполнение на сервер и заменить транспорт.

---

## Сессия 5.1 — Схема базы и снимок мира

**Что сделать**

- `db/schema.ts` — все таблицы §9 ТЗ: `users`, `islands`, `island_state`, `villagers`, `buildings`,
  `journal`, `visits`, `gifts`, `friends`. Миграции через Drizzle.
- Гибридное хранение по §1 ТЗ: реляционные поля для того, что ищется (пользователи, острова, визиты),
  `jsonb` для тела мира (патч, ресурсы, метаданные).
- `island_state.world_patch` — **только отличия от генерации**. Остров весит килобайты.
- Поле `version` в `island_state` — на будущие миграции формата сохранений.
  Сразу написать загрузчик, который умеет читать старую версию и повышать её.
- Сериализация и десериализация состояния — чистые функции в `shared`, с тестом на круговой проход:
  состояние → JSON → состояние даёт исходное побитово.

**Готово, когда**

- [x] Миграции применяются на чистой базе
- [x] Тест кругового прохода зелёный
- [x] Полный остров с 60 жителями и 250 зданиями сериализуется в разумный объём (ориентир: < 500 КБ)

## Сессия 5.2 — Авторизация по magic-link

**Что сделать**

- `POST /auth/magic-link` `{ email }` — одноразовый токен с коротким сроком жизни, письмо со ссылкой.
- `GET /auth/callback?token=…` — обмен токена на JWT в **httpOnly cookie**. Паролей нет вообще (§1 ТЗ).
- `GET /me` — текущий пользователь.
- Отправка почты через абстракцию `MailTransport`. Две реализации: консольная для разработки
  (ссылка печатается в лог) и реальная — см. открытый вопрос №1 в `docs/PLAN.md` §9.
- Ограничения: не более N писем на адрес в час, токен одноразовый и сгорает при использовании.
- Тексты писем по тону §8 ТЗ: спокойно, без восклицаний, без маркетинга.

**Готово, когда**

- [x] Вход по ссылке из письма работает; сессия переживает перезагрузку
- [x] Повторное использование токена отклоняется
- [x] На разработке можно войти без настроенной почты

## Сессия 5.3 — REST островов

**Что сделать**

- `POST /islands` `{ name }` — создаёт остров: сид, стартовое состояние, **4 жителя** (§9 ТЗ),
  короткий `visit_code`.
- `GET /islands/:id` — полное состояние. Поле для результата догона предусмотреть сразу,
  сам догон появится на M6.
- `GET /islands/:id/journal?after=` — заготовка, наполнится на M7.
- Права: остров отдаётся только владельцу; гостевой доступ по коду — M8.
- Клиент переходит на серверное состояние: `localStorage` из M2.3 удаляется вместе с пометкой
  `TEMPORARY: replaced in M5.3`.

## Сессия 5.4 — Команды на сервере

**Что сделать**

- `POST /islands/:id/commands` `{ commands: Command[] }` — **единственная точка мутации** (§9 ТЗ).
- Сервер валидирует всё тем же кодом из `shared`, что и клиент: наличие ресурсов, проходимость,
  лимиты, права. Ни одной ветки логики, дублирующей клиентскую.
- Ограничения (§9 ТЗ): 30 команд в секунду на пользователя, не более 64 правок в одном `terraform`,
  разумный потолок на размер тела запроса.
- Ответ: принятые команды и по каждой отклонённой — причина кодом.
- Запись результата в базу транзакцией: либо применились все команды пакета, либо ни одна.

**Тесты (обязательно)**

- Команда с несуществующим зданием, чужим островом, нехваткой ресурсов — отклоняется.
- Подделанные значения в теле запроса не влияют на результат: сервер считает всё сам.
- Превышение лимитов отклоняется без падения сервера.
- Параллельные пакеты команд не создают дублей и не теряют изменения.

**Готово, когда**

- [x] Команды из консоли браузера не дают ресурсов и не двигают время
- [x] Валидация на клиенте и сервере — один и тот же код

## Сессия 5.5 — Живой тик и WebSocket

**Что сделать**

- `sim/liveLoop.ts`: живая симуляция раз в 10 реальных секунд — **только для островов, у которых
  есть онлайн-игрок** (§12 ТЗ). Офлайн-острова не тикают вообще.
- `ws/hub.ts`: подключение `/ws?islandId=`, авторизация по той же cookie, комнаты по островам.
- Сервер шлёт `tick`: дельты ресурсов, состояния агентов, события. Клиент шлёт только `command` (§9 ТЗ).
- Между тиками клиент **интерполирует движение сам** — сеть не должна нести позиции каждый кадр.
- Переподключение: разрыв связи не ломает игру; при возврате клиент получает полное состояние и
  продолжает. Индикатор связи — спокойный, без тревоги.
- `lastTickAt` пишется серверным временем и только сервером.

**Готово, когда**

- [x] Две вкладки одного острова показывают одно и то же
- [x] Разрыв и восстановление связи проходят незаметно
- [x] Сервер не тикает острова без игроков

## Сессия 5.6 — Оптимистичный клиент

**Что сделать**

- Заменить локальный транспорт шины команд (M2.1) на сетевой. **Правка одного файла** — если
  выяснится, что нужно больше, значит слой команд где-то обходили; это надо найти и исправить.
- Клиент применяет команду сразу и держит её в очереди неподтверждённых.
- Подтверждение — команда уходит из очереди. Отказ — **мягкий визуальный откат**:
  здание тихо исчезает, воксель возвращается на место. Никаких модальных окон (§9 ТЗ).
- Расхождение серверного состояния с предсказанным чинится дельтой, а не полной перезагрузкой сцены.
- Обратная связь на отказ — короткий тост в тоне §8 ТЗ, объясняющий, что делать дальше.

**Тесты (обязательно)**

- Отказ сервера откатывает ровно одну команду, а не всю очередь.
- Очередь из нескольких команд применяется и подтверждается по порядку.
- Расхождение состояний сходится за один цикл синхронизации.

**Готово, когда**

- [x] Интерфейс отвечает мгновенно, при этом решает сервер
- [x] Откат не пугает и не мигает

## Чего не делать на этом этапе

- Не делать догон и офлайн-прогресс — это M6. Пока остров не тикает, пока игрока нет, и это ожидаемо.
- Не делать гостевой доступ, подарки и друзей — это M8, хотя таблицы уже созданы.
- Не делать OAuth. §1 ТЗ прямо говорит: добавляется позже одной ручкой.
- Не углубляться в античит. §9 ТЗ: соревнования нет, красть не у кого — хватит серверного счёта
  и лимитов частоты.
- Не делать горизонтальное масштабирование, шардирование, очереди сообщений. Один процесс,
  живая симуляция только для онлайн-островов — этого достаточно на годы вперёд.
- Не делать админку и панель модерации. Свободного текста в игре нет, модерировать нечего (§9 ТЗ).

## Что получилось на этапе

Обещание из шапки этапа сбылось буквально: замена локального исполнителя команд на сетевой —
это правка одного файла, `net/commands.ts`. Слой команд с M2.1 никто не обходил, и переезд
на сервер ничего в остальном клиенте не потребовал.

Что изменилось в устройстве игры:

1. **Мир считает сервер.** Воркер симуляции с клиента убран целиком: жители, производство
   и время живут в одном месте, и это место — сервер. Клиент рисует, предсказывает команды
   и сглаживает движение между тиками.
2. **Клиента без сервера больше нет.** `localStorage` из M2.3 удалён вместе с пометкой
   `TEMPORARY`. Это осознанная потеря: играть без базы теперь нельзя, зато не осталось
   второго, расходящегося источника правды.
3. **Ключи жителей и зданий составные** — `(island_id, id)`. Симуляция даёт им короткие
   островные имена (`villager-1`), и на втором острове они повторяются; глобальная уникальность
   ради одной строки в базе заставила бы врать весь остальной код.
4. **Пустой остров не считается вовсе.** Тик идёт только там, где кто-то есть, и это условие
   того, чтобы один процесс тянул тысячи островов. Проверено: после отключения последнего
   клиента номер тика замирает.

Заодно на этапе нашлись и починены две вещи, не относящиеся к серверу: часы жителей шли
от полуночи, а солнце — от девяти утра (M4), и `findScenicSpots`/`findSpawns` жили копиями
в клиенте и на сервере — теперь они в `shared`, потому что расхождение в местах, где начинается
жизнь острова, развело бы жителей с первого же тика.
