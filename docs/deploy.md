# Запуск и эксплуатация

Три части, как в §1 ТЗ: клиент — статика, сервер — постоянный процесс, база — managed Postgres.

> **Честно о состоянии.** Конфигурация написана и вычитана, но **развёртывание не выполнялось**:
> в среде, где собирался проект, нет ни учётных записей площадок, ни доступа наружу. Всё, что
> проверено по-настоящему, отмечено ниже словом «проверено». Остальное — инструкция, которую
> предстоит пройти первый раз вживую.

---

## Что где живёт

| Часть | Где | Почему так |
|---|---|---|
| Клиент | Netlify или Vercel, статика из `apps/web/dist` | Ни серверного рендеринга, ни функций не нужно |
| Сервер | Fly.io или Railway, постоянный процесс | Тики уходят игрокам по WebSocket — serverless не подходит |
| База | Managed Postgres той же площадки | Резервные копии и обновления не наша забота |

Файлы: `apps/server/Dockerfile`, `fly.toml`, `apps/web/netlify.toml`.

## Переменные окружения

Сервер не стартует, если обязательное не задано или задано неверно — проверка в `config.ts`.

| Переменная | Обязательна | Что это |
|---|---|---|
| `DATABASE_URL` | да | Строка подключения. На Fly появляется сама после `fly postgres attach` |
| `SESSION_SECRET` | да в бою | Чем подписывается сессия. Без своего значения сервер в бою не запустится |
| `PUBLIC_URL` | да | Адрес сервера: попадает в ссылку из письма для входа |
| `WEB_ORIGIN` | да | Адрес клиента: нужен для CORS и cookie сессии |
| `HOST`, `PORT` | нет | По умолчанию `0.0.0.0:3000` |
| `NODE_ENV` | нет | По умолчанию `development`. **В общий `.env` не кладётся** — см. `docs/perf.md`, M9 |

Клиенту нужна одна переменная — `VITE_SERVER_URL`; она попадает в бандл, поэтому секретов
в ней быть не может.

Сгенерировать секрет:

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

## Порядок первого развёртывания

```sh
# 1. База
fly postgres create --name gavan-db
fly postgres attach gavan-db --app gavan

# 2. Секреты
fly secrets set \
  SESSION_SECRET="$(node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))")" \
  PUBLIC_URL="https://gavan.fly.dev" \
  WEB_ORIGIN="https://gavan.netlify.app"

# 3. Сервер
fly deploy

# 4. Миграции — один раз после первого развёртывания и после каждой новой.
#    Отдельным шагом намеренно: миграция на старте означала бы, что два экземпляра
#    сервера начнут её одновременно.
fly ssh console -C "cd /app/apps/server && pnpm db:migrate"

# 5. Клиент
VITE_SERVER_URL=https://gavan.fly.dev pnpm --filter @gavan/web build
netlify deploy --prod --dir apps/web/dist
```

## Резервные копии — **проверено**

Бэкап без проверенного восстановления бэкапом не считается. Поэтому скриптов два, и второй
не просто восстанавливает, а сразу считает, что приехало.

```sh
DATABASE_URL=postgres://… ./scripts/backup.sh backups
DATABASE_URL=postgres://… ./scripts/restore.sh backups/gavan-20260806T212504Z.dump
```

Проверка пройдена вживую на копии рабочей базы: 42 острова, 42 игрока, 168 жителей,
12 зданий, 5 записей дневника, 1 подарок в порту, 7 заплаток мира. Целостность —
у каждого острова есть состояние. После этого сервер поднят **на восстановленной базе**,
и остров открылся по гостевому коду со своими жителями, тиком и заплатками мира.
Это и есть критерий: не «настроен бэкап», а «бэкап развёрнут на чистой базе, и остров открылся».

Managed Postgres делает копии сам; эти скрипты нужны для второй копии за пределами площадки
и для проверки, что восстановление работает не только в теории.

## Ошибки — **проверено**

На игрока ошибка не вываливается техническим текстом (§11 ТЗ):

- **Сервер.** Отказы, которые мы сами сформулировали (400, 403, 404, 429), уходят как есть —
  их текст написан там, где известно, что делать дальше. Всё, что 500 и выше, превращается
  в одну строку «Что-то не сложилось на нашей стороне. Остров цел, попробуй ещё раз» плюс
  идентификатор запроса, чтобы жалобу можно было найти в логе. Ни стека, ни имени таблицы,
  ни адреса базы в ответе нет. Проверено тестом, который бросает ошибку с адресом базы
  внутри и убеждается, что наружу он не попал.
- **Клиент.** Падение React показывает «Панели сломались, а остров цел. Обнови страницу»
  и кнопку. Полный стек уходит в консоль браузера.

## Аналитика — **проверено**, только агрегаты

`GET /stats` отдаёт шесть чисел: островов, игроков, распределение по главам, островов
с активностью за сутки, визитов, среднее число зданий на остров. Всё.

Чего здесь нет и не будет: событий отдельного игрока, воронок, идентификаторов устройств,
внешних трекеров, рекламных пикселей. Тест перебирает ответ и требует, чтобы каждое значение
было числом, а символа `@` в теле не встречалось вовсе.

Смотреть после запуска стоит три вещи (§12 ТЗ): доходят ли игроки до второй главы,
возвращаются ли, ходят ли друг к другу. Если не доходят — чинить надо игру, а не показатели.

## Приватность — **проверено**

- Почта используется только для входа. Больше нигде она не показывается и наружу не отдаётся —
  тест проверяет, что в гостевом снимке нет ни почты, ни идентификатора владельца.
- Свободного текста в игре нет вообще: и подарок, и открытка выбираются из готового набора
  по идентификатору. Поэтому нет и модерации.
- Данные острова доступны владельцу и гостям по коду. Посторонний получает 403 — проверено тестом.
- Внешних скриптов на странице нет ни одного. `Content-Security-Policy` в `netlify.toml`
  это закрепляет: `default-src 'self'`.

## Чего проверить не удалось

- **Само развёртывание.** Ни `fly deploy`, ни выкладка клиента не выполнялись.
- **Сборка Docker-образа.** В среде нет демона Docker, `Dockerfile` не собирался ни разу.
- **Частота кадров в бою.** См. `docs/perf.md`: нужна машина с настоящей видеокартой.
